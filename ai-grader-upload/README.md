# AI 判分系统

老师出题并写好评分标准 → 学生提交答案 → AI 给出分数和理由 → 老师可以改分确认。

一个在本机运行的小应用，演示「AI 参与作业批改」的完整流程。

---

## 功能

- 载入题目与评分标准（内置示例题库，也可手动输入）
- 学生提交答案
- AI 按评分标准逐条打分，输出总分、逐条明细和总体评语
- 老师可修改分数并确认，记录留存，支持导出 CSV
- 附效果测试：同一道题的多份答案，AI 与人工评分对比

## 技术栈

| 部分 | 选型 | 说明 |
|---|---|---|
| 页面 | Streamlit | 单个 Python 文件即可生成网页，不需要写前端 |
| 大模型 | DeepSeek API | 兼容 OpenAI 接口，使用 `openai` SDK 调用 |
| 配置 | python-dotenv | API Key 存放于 `.env`，不写入代码 |

## 运行

```bash
pip install -r requirements.txt

# 把 .env.example 复制为 .env，填入自己的 DeepSeek API Key
streamlit run app.py
```

打开 http://localhost:8501 即可使用。

> 未配置 API Key 时会进入「模拟打分」模式，用于验证流程是否跑通；
> 配置后会切换为真实大模型打分。

## 两个关键设计

### 1. 让模型先判档，再给分

提示词要求模型对每一条评分标准先判断属于哪一档：

| 判定 | 给分 |
|---|---|
| 完全达到 | 该条满分 |
| 部分达到 | 该条一半 |
| 未达到 | 0 分 |

并要求每条说明必须引用学生答案原文作为依据。
这样做的目的是避免模型给出笼统的「印象分」。

### 2. 总分由程序计算，不采用模型自报的总分

实测发现：模型逐条打分是准的，但它自报的总分经常算错。

例如对同一份答案，它逐条给出 `20 + 20 + 15 + 0`，总分却写成 `70`。

因此总分改为由程序对逐条得分求和，模型只负责逐条判分。

## 效果验证

6 份不同水平的答案，同一道题、同一套评分标准，AI 与人工各评一遍：

| 指标 | 结果 |
|---|---|
| 平均绝对分差 | 15 分 |
| 人工平均耗时 | 30.2 秒 / 份 |
| AI 平均耗时 | 2.0 秒 / 份 |
| 速度对比 | 约快 15 倍 |
| 人工耗时波动 | 7.9 ~ 56.1 秒 |
| AI 耗时波动 | 1.7 ~ 2.2 秒 |

完整数据见 [`测试数据表.csv`](./测试数据表.csv)。

**观察到的局限**：AI 对「能输出结果、但计算结果错误」的答案偏宽松。
例如把数字拼接成 `3015` 的答案，人工判 0 分，AI 给了 55 分。
说明模型更关注代码形式，人工更关注实际运行结果。
